# Console logs

Maintainer note: `.temp/tests/` contains optional, disposable local harnesses, excluded from public downloads. Commands below require those retained harnesses; historical evidence is not shipped or regenerated by a build.

Configure `logDirectories` with a label and logs directory for each Workbench or independent client profile. See [example configuration](../configuration.example.json). Paths resolve relative to the configuration file and support `${Documents}`. No editor connection or Ghidra is needed. Only `console.log` is read; no merged streams or alternate files.

A source may contain dated `logs_.../console.log` sessions, a direct `console.log` written by Workbench's `-logsDir`, or both. The direct file is listed as session `configured`; candidates are ordered by console modification time. Reload diagnostics still require a file owned by the selected process, and session IDs cannot traverse outside the configured root.

- `log_sessions()` lists configured sources; `log_sessions(source: "peer1")` lists up to 10 newest session folders (limit 1–20).
- `log_read(source: "workbench")` selects the newest listed console and the latest reload/initial compilation through the observed file end. A missing console or unrecognized boundary returns an error; it never silently switches sessions or returns a tail.
- `severity: "error"`, `"warning"`, or `"info"` and `category: "SCRIPT"`/`"RESOURCES"`/`"NETWORK"` narrow results. Filters combine. Category and search are case-insensitive.
- `workbench_reload_scripts` includes fresh process-owned errors in `reload_failed` results when correlation is verified; see [inline reload diagnostics](workbench-scripts.md#inline-failure-details-and-retained-results). If those diagnostics are unavailable or insufficient, start with `log_read(source: "workbench", severity: "error")`. Broaden to context or the full cycle if that does not explain the failure. The general default still includes ordinary runtime messages.
- `query: "allowed=0"` searches literal text, including ordinary runtime messages. Set `regex: true` for a regular expression (512-character pattern limit, 100ms match timeout, 10s overall scan limit). Regex errors/timeouts return errors, not partial matches.
- `cycleOffset: 1` selects the previous cycle through the line before the next cycle; offsets 0–20 are supported. A cycle starts at the outer `SCRIPT : SCRIPT : Reloading game scripts`; the repeated plain heading and validation/compilation phases remain inside it. Initial `Compiling GameLib scripts`/`Compiling Game scripts` opens a startup compilation when no reload is active. A new outer reload begins a new cycle even if the preceding attempt has no completion marker.
- `scope: "session"` explicitly reads the whole selected session; `scope: "tail"` selects the last `limit` physical lines before filtering. `session` can name an older `logs_YYYY-MM-DD_HH-MM-SS` folder from the listing.
- For context around a match, read `scope: "session", startLine: <match line minus a few>, limit: 20` without filters. Use a minimum start line of 1. Untimestamped stack lines inherit the preceding category/severity; literal/regex searches match individual lines.

The response includes file path, session header, revision, scope bounds, cycle start and optional completion timing marker, severity/category counts, matching-line count, and numbered raw lines. Counts cover the entire selected scope **before filters**, including physical continuation lines. These are mechanical summaries, not root-cause or success judgments. A timing marker does not prove compilation/reload success. File order remains authoritative across midnight; individual timestamps are preserved as local clock text, not converted to invented dates. The header preserves the session's local/UTC date information. Newest is not proof of running or of the correct project; Workbench and peer sessions are independent.

Results do not repeat a fixed `evidence` explanation. Usage guidance lives here and in the tool description. Existing `textTruncated`, `truncated`, and `nextLine` fields identify clipping and paging; `partialLastLineOmitted: true` appears only when the snapshot excludes an unfinished trailing line. Severity counts are log-line counts, not counts of distinct problems.

Output defaults to 80 entries, at most 200 and approximately 24KB of serialized entries plus bounded metadata. Pass the returned `session`, `revision`, and `nextLine` as `startLine` with the same scope/filters to continue. Each revision fixes a byte boundary: ordinary appends remain outside that snapshot and do not invalidate paging. Omit revision to refresh. Revisions bind the path, creation time, prefix length and SHA-256 of its bytes. Both passes hash that same prefix; truncation, replacement or overwritten bytes return explicit errors. Restart without revision after rotation. An unfinished trailing line is omitted until a fresh snapshot includes its newline. This is read-only and safe to retry.

Each line is clipped to 2,000 characters with `textTruncated: true`; the full original remains in the reported file. A page can split a multiline event: `continuation` and `nextLine` make that visible. Scans stream the selected prefix twice without caching its contents, bounded to 256MiB and 10 seconds; larger/over-budget reads fail explicitly. No full-file dumps, background indexing or process mutations.

Validation: `dotnet run --project .temp/tests/ReforgerMcp.LogTests -- <server-dll> <fresh-evidence-directory>` runs boundary/filter/paging/failure fixtures and real MCP calls. Real-file checks use the inspected Workbench session `logs_2026-10-20_18-55-53` and newest PeerPlugin1 session under Windows Documents. It creates synthetic files only in the supplied evidence directory and never changes source logs or launches/reloads the game. MCP response/timing evidence is retained there.
